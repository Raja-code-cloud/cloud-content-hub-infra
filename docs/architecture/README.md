# Architecture Overview

This document describes the high-level infrastructure architecture for the Cloud Content Hub platform on Azure.

## Design Principles

1. **Separation of concerns** â€” Infrastructure is managed independently from application repositories.
2. **Modularity** â€” Reusable Terraform modules encapsulate resource patterns.
3. **Environment parity** â€” dev, stage, and prod share the same module compositions with environment-specific parameters.
4. **Security by default** â€” Private endpoints, managed identities, and Key Vault for secrets.
5. **Observability** â€” Centralized logging, monitoring, and alerting from day one.

## Module Dependency Order

When implementing resources, modules should be composed in this order:

1. `naming`
2. `common` (shared foundation)
3. `resource-group`
4. `networking`
3. `managed-identity`
4. `key-vault`
5. `log-analytics`
6. `application-insights`
7. `monitor`
8. `storage`
9. `acr`
10. `postgres`
11. `redis`
12. `container-app-environment`
13. `container-app`
14. `alerts`
15. `budget`

## Environment Strategy

| Environment | Purpose                          | Subscription        |
|-------------|----------------------------------|---------------------|
| dev         | Development and experimentation  | Non-production      |
| stage       | Pre-production validation        | Non-production      |
| prod        | Production workloads             | Production          |

## State Management

Terraform remote state will be stored in Azure Storage with state locking. Configuration will be added per environment when environments are implemented.
